#### 洞见1 判读 (数字均来自上方真实测量)

- prefill 随 prompt 长度算力利用率从 15.6% 升至 77.0% (P=4096), 趋近实测 GEMM 峰值 => 计算受限, 与洞见 1 一致。
- 单步 decode 算力利用率最高仅 0.081% (远低于 prefill) => 明确*非*计算受限。此 0.49B 小模型上 延迟近似恒定 (27~29ms, 随上下文 32x 增长几乎不变) 且带宽利用 仅 6~7% => 受*固定单步开销*(逐层 kernel 启动/Python 循环)主导, 尚未饱和 HBM。
- 7B 单步 decode 仅读权重 (15.2GB) 即有 ~24ms HBM 底线 (实测 copy 带宽 625.5GB/s), 远超 0.5B 的固定开销 => 7B decode 必然带宽受限。KV 读占比随上下文与 batch 放大: ctx=131072 时 batch1=33%, batch16=89%, batch64=97% => 长上下文/批量下 KV 读流量成为 decode 带宽主因, 直接支撑压 KV 的收益 (洞见 1/2)。 实测 7B decode 落点待模型下载完成后用本脚本 --measured-model 7B 复跑。
